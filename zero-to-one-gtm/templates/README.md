# GTM search

This folder is the evidence for a zero-to-one go-to-market search. The procedure lives in the personal skill `zero-to-one-gtm`.

`STATUS.md` is the current stage. Its header is what an agent or Grok Bot reads first.

## Layout

- `thesis/` — versioned GTM thesis. Every line is an assumption until evidence says otherwise.
- `assumptions/` — desirability, feasibility, and viability, riskiest first.
- `evidence/` — strength of each claim, with product-delivered value kept apart from founder manual work.
- `discover/` — interview guide, rings, notes, vocabulary, patterns, and disconfirming evidence.
- `experiments/` — one board and one card per test. The pass/fail threshold is set before the test runs.
- `customers/` — one file per person and a register of the cohort.
- `design/`, `activate/`, `playbook/` — stay empty until their gates open.
- `inbox/raw/` — drop a note here. After it is filed, it moves to `inbox/processed/`.
- `bot/routine-prompt.md` — prompt text for a future Grok Bot routine. Routines are not wired yet.

## How to use it

Describe the product. The agent writes thesis v0, a Ring 0 note, and ten blank slots for people you already know.

After that, the useful asks are: who should I talk to, log this conversation, draft a message, draft a post, where are we, what is due, weekly review, design the next experiment.

You send the messages. You have the conversations. You confirm the weekly decision. The agent does not advance the stage on its own.
